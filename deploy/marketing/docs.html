Technical overview

Architecture

BidShard ships as self-hosted software you install on your VPS or dedicated server. This page describes what actually runs on your metal — not a cloud SaaS control plane. Engineering detail for contributors lives in the vendor tree (docs/ARCHITECTURE.md).

Overview

The system splits into a hot path (accept or reject clicks and impressions under millisecond budgets) and a cold path (campaign CRUD, billing, reports, ML batch jobs, outbox workers). Your traffic never passes through BidShard's servers in the default delivery model — only the license JWT and support chat are vendor-side.

HTTP 202 on /track means the tracker accepted and validated the event on the ingest path. It does not mean Postgres or ClickHouse already committed the row — that happens asynchronously via the processor.

Default stack on your server

A typical single-VPS install runs these processes (systemd units from the installer):

Process Role Default port
Nginx (OpenResty) TLS, rate limits, early blacklist, shard routing to tracker pool 8180 / 443
tracker Click/impression ingest, filter chain, budget enforcement, async event enqueue 8181–8184
control Admin API, campaign mutations, outbox workers, payment webhooks 8188
processor Consumes Redis streams (or broker WAL) → settles Postgres + batches ClickHouse 8186

Redis Hot-path debit/dedup, streams, pub/sub config reload 6479+ (sharded)

Sizing note: ClickHouse is RAM-hungry on a single VPS. For a comfortable all-in-one install (ClickHouse + Redis + Postgres + tracker pool), plan at least 4–6 vCPU and 12 GB RAM plus NVMe disk. Routing-only pilots can start smaller; an undersized budget VPS often hits ClickHouse OOM — that is an ops sizing issue, not a license defect. See hardware sizing below.

License verification uses an offline Ed25519 JWT file on disk — no recurring phone-home to issue ingest tokens. Feature flags, host activations, and export limits are encoded in the JWT per SKU. Campaign and event volume are not license-capped when catalog values are zero.

What happens on a click

  1. Edge (nginx) — optional early reject: per-campaign rate limit, circuit breaker, IP blacklist, ASN policy. Config is mirrored into worker memory on a timer; access phase does not call Redis per request.
  2. Tracker parse — HTTP/1 handled by gnet (not net/http on the hot path). /track requires Content-Length; chunked bodies are rejected (parity with edge policy).
  3. Local filters — license, geo, schedule, device signals, consent, and rule-based fraud checks run in-process. ML model inference does not run here; the tracker may read a precomputed fraud-boost snapshot from Redis when your tier includes it.
  4. Redis unified filter — at most one synchronous Lua script per accepted event for budget debit and dedup (zero scripts when local-quota full-skip mode is eligible). Campaign keys use a Redis hash tag so multi-key atomicity stays on one shard master.
  5. Async enqueue — accepted events go to a Redis stream or optional mmap broker WAL via a reserved slot in the producer queue. If enqueue fails after debit, the budget is rolled back.
  6. Processor — background workers batch into Postgres (settlement) and ClickHouse (analytics).

/click runs the same filter chain and returns a redirect. /openrtb/bid runs an in-process RTB auction only — not the full filter chain (Network tier, live mode).

Antifraud semantics (no marketing shortcuts)

  • Hard reject — HTTP 403; event is not debited.
  • Silent reject — HTTP 202 to the visitor (decoy accept); flagged in analytics so funnels stay clean. Does not auto-flip campaign settings in Postgres.
  • IVT detector (Pro+) — batch rules on ClickHouse; can enqueue blacklist/boost actions via the admin outbox.
  • ML fraud scorer (Scale+) — batch LightGBM in a sidecar writes boost keys to Redis; the tracker reads a precomputed fraud-boost snapshot on ingest (map lookup only — no model inference on /track).
  • Margin Guard (Starter+) — timer worker (default 5 min) on Postgres ledger and ClickHouse placement stats; breach enqueues internal routing pause (Redis budget removal or placement block). Not ad-network API pause unless Enterprise platform sync is licensed. Skips when ClickHouse lag > 5 min.

Admin, billing, and reports

control is a modular monolith: one process exposes /api/v1/* and runs in-process workers. When you PATCH a campaign, the mutation and an outbox_events row are written in the same Postgres transaction. An outbox worker (poll ~20 ms) applies Redis side effects and triggers tracker registry reload via pub/sub.

The tracker does not poll Postgres on each request — it reads an in-memory snapshot refreshed from Redis. Payment webhooks and ledger entries are cold-path only; the processor does not insert balance_ledger rows.

Data stores

PostgreSQL

Campaigns, budgets, team RBAC, payment state, transactional outbox. Source of financial truth after processor settlement.

Redis

Per-shard budgets, dedup locks, ingest streams, fraud blacklists, ML boost snapshots. Standalone masters + Sentinel — not Redis Cluster on the hot path.

ClickHouse

Event analytics, report aggregates, IVT/ML feature reads. Not consulted synchronously on /track accept.

Campaigns are sharded: slot = CRC32C(campaign_id) & 1023 maps to a Redis shard and tracker listener. Edge slot map and Go must stay in sync (installer publishes the map).

Hardware sizing

Planning guide only — not a throughput guarantee. Start here, then scale with traffic, antifraud depth, and whether reporting and bidding run on the same box or separate hosts.

Honest limits

  • We do not host your traffic or guarantee uptime on your VPS — you operate the box.
  • Edge and XDP can drop known bad IPs; rotating proxies may still reach the tracker — L7 rules apply there.
  • BROKER_SHADOW_MODE shadows processor CH ingest only; tracker WAL writes are live when broker-primary is enabled.
  • LOCAL_QUOTA_MODE=shadow exercises local quanta but still runs sync Redis Lua; only live can skip it when eligible.
  • License limits (hosts, tenants, features, export chunk size) are enforced per tier — see pricing.
